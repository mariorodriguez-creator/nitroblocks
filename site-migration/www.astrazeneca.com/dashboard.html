Known Limitations
What this analysis cannot tell you
🚫
JS-rendered content invisible
The filterable listing pages (az-filter-items), investor stock widget (custom-price), and Sustainability Vue/Vuetify dashboards are client-side rendered. Their full component structure required live browser inspection beyond CSS class analysis.
📁
DAM assets counted as pages
The content section contains 173 DAM asset URLs (/content/dam/az/…) — these are images/files, not HTML pages. They skew the URL total but require no migration effort beyond asset management.
🌏
Country sites partially sampled
135 country-site pages sampled at 50%. Thailand's ~101 pages are mostly press releases matching the same template as global. Deeper country-specific editorial patterns may exist in unsampled pages.
🔌
Third-party integrations invisible
Veeva ID footer, Adobe Analytics datalayer, OneTrust cookie banner, Brightcove video, reCAPTCHA, and the AZ stock price feed are loaded dynamically. Each is a separate integration story not reflected in the block count.
🏗️
CSS classes = structural signals only
The source site's CSS (AEM Classic framework) uses tablesaw-enhanced, modal-content, block-wrapper on 85–100% of pages. These are layout utilities, not EDS block identifiers. Semantic analysis took precedence over CSS analysis for block naming.
📐
Block count ≠ authoring complexity
11 new blocks is a component count, not a direct story-point count. The header mega-nav and filterable-list together represent more effort than 6 simpler blocks combined. Effort sizing adjusts for this — see Effort Sizing tab.

Mega-nav underestimation — Multi-tier dropdown, search, country-switcher, sticky scroll. #1 delivery risk. Prototype first; allocate 5–8 days.
📈
Stock ticker API contract — Live IR data requires approved vendor + compliance sign-off. May block Investor Relations template.
🔍
Query-index schema undefined — filterable-list depends on EDS query-index being configured with correct columns. Must be done in Week 1.
🌿
Sustainability dashboards — Vue/Vuetify + OpenLayers rebuild in vanilla JS. Consider iframe interim while native rebuild is validated.
📷
Responsive image CLS — Dual hero images (desktop/mobile) may download both. Remove unused image from DOM in block decoration.

Define EDS query-index columns (title, date, tags, path) before leaving Phase 1 — required for filterable-list in Phase 2. Lighthouse 100 baseline must be established here and defended throughout.
Phase 2
Core Content Templates
Weeks 3–6 · ~25 story points
image-panel block filterable-list block featured-stories block cards (therapy / people / events) Template: Homepage Template: Hub Page Template: Article Detail Template: Press Release Template: Simple Text
image-panel unblocks the Homepage and all Hub Pages. filterable-list unblocks What Science Can Do and Media Centre — the highest-volume content templates on the site. featured-stories completes the Homepage. By end of Phase 2, 12 of 19 templates are importable.
Phase 3
Supporting Blocks
Weeks 6–8 · ~20 story points
quote (feature) variant tabs (jump-nav) variant carousel (content) accordion (faq) table (downloads) language-selector Template: Country Sites Template: Filtered Listing Template: AZ Suppliers
Smaller, well-scoped blocks that enhance existing templates. Jump-nav and carousel are needed for Our Company and Therapy Area full fidelity. Accordion serves both AZ Suppliers and Investor Relations FAQs. Content authors can begin authoring and testing during this phase.
Phase 4
Specialist Features
Weeks 8–11 · ~28 story points
stock-ticker (pending API contract) media-gallery block data-map (Leaflet rebuild) data-dashboard (vanilla JS) Template: Investor Relations Template: Sustainability Dashboard Template: Media Library QA · Lighthouse 100 · WCAG AA
Highest-complexity individual blocks, each serving only 1 template. Stock ticker is deliberately last — it depends on a vendor contract and compliance sign-off that should be initiated in Phase 1. Sustainability dashboards: consider an iframe interim if vanilla JS rebuild isn't complete before go-live date.
✓ Key Success Factors
• Content-first approach — model every template in Word/Google Docs before writing EDS code
• Prototype the mega-nav first — it blocks everything; budget 5–8 days and get approval early
• Define query-index schema in Week 1 — filterable-list, featured-stories, and news feeds all depend on it
• Lighthouse 100 baseline in Phase 1 — easier to maintain than recover after regressions
• Stock ticker vendor early — engage AZ IR tech team Week 1; don't let it be a Phase 4 surprise
• Authoring workshop before Phase 2 — AEM Classic authors need Word/Google Docs onboarding for every new block type
